---
title: "Bootstrap identity and credentials"
description: "Create an initial admin or a service API key with Core's supported bootstrap commands."
---

These commands write to the database selected by `DATABASE_URL`. Run them from the SNEWSE repository root only after confirming the target database and protecting any generated secret output.

## Seed an admin

Set `SNEWSE_ADMIN_EMAIL` and `SNEWSE_ADMIN_PASSWORD`. You can also set `SNEWSE_ADMIN_NAME` and `SNEWSE_ADMIN_ROLE`. Then run:

```powershell
pnpm auth:seed-admin
```

Success prints `Admin user ready` with the email and role. When the email already exists, the command verifies and updates its name and role but leaves its password unchanged. The [admin CLI](https://github.com/coreyconner/snewse/blob/master/apps/core/src/infrastructure/auth/cli/seed-admin.ts) also accepts matching `--email`, `--password`, `--name`, and `--role` arguments.

## Create a service API key

Set `SNEWSE_API_KEY_USER_EMAIL`. Optional values include the service user's password, name, role, and key name. Then run:

```powershell
pnpm auth:create-api-key
```

Success prints the new API key once. Store it in the intended secret manager immediately; terminal output is the only supported delivery shown by the CLI.

The command creates a write-permission key with the `sn_` prefix. If the email already belongs to a user with another role, it refuses to change that role unless you explicitly pass `--allow-existing-user-role-change true`. Prefer a dedicated service identity.

<Warning>
  Both commands change authentication records. Confirm `DATABASE_URL` before running them, and do not put passwords or returned API keys in source control, documentation, logs, or screenshots.
</Warning>

Core's [authentication guide](/developer/core/authentication) owns session and credential semantics. The [API-key CLI](https://github.com/coreyconner/snewse/blob/master/apps/core/src/infrastructure/auth/cli/create-api-key.ts) is the authority for current flags and safeguards.
